As a tester we are more involve in system testing.
we can say it as a black box tester.
SYSTEM TESTING:
  ->testing overall functionality of the application with respect to customer requirement.
  ->After completiton of integration testing, System testing we will do.

In system testing focusing more on:
->GUI testing
->Usability testing
->Functional testing
->Non-Functional testing

GUI TESTING:
  -> testing user interface of an application.
  -> GUI includes all elements like(menus,checkbox,button,colors,fonts,sizes,icons,images)

USABILITY TESTING:
  ->In this testing, we ensure easiness of an application.
  ->testing whether the our s/w helping others or not?.

FUNCTIONAL TESTING:
  ->Functionality is behaviour of application.
  ->Functional testing about how your feature should work.

  Under functional testing, we do following:
	1)Object Properties Testing
 	2)Database Testing
	3)Error Handling
	4)Calculations/Manipulations Testing
	5)Links Existence & Links Execution
	6)Cookies & Sessions

   1.Object(all web elements) properties Testing:
        eg: 1.testing box can enable or not,disable or not
            2.when i select male radio button,female should be disable.
            when i select female radio button,male should be diable.
   2.Database Testing/Backend testing:
        ->Mainly focusing on DML(Data Manupulation testing) operations.
          (delete,insert,create,update)
	->GRAY BOX TESTING: combinatin of black box and white box testing.
        Reason: performing testing at UI part-->black box.
                writing queries and checking in the DB--> white box.
      what we actually do in db testing?
       ->Table level validations(Column type, column length, no of columns...)
       ->Relation between the tables (Normalization)
       ->Functions
       ->stored Procedures
       ->Triggers
       ->Indexes
       ->views
         etc.
        
   3.Error Handling Testing:
   --------------------------
   ->Testers verifty the error messages while performing incorrect actions on the application.
   ->Error messages should be readable.
   ->User understandable/Simple language.

  Incorrect data
  Invalid user ----more relevant error message than above

  4.Calculations?Manipulations Testing:
-----------------------------------------
  ->Testers should verify the calculations are working properly or not.
     eg:  In Gpay: TOTAL BALANCE: 10000
                   WITHDRAWL: 5000
		   CURRENT BALANCE SHOULD SHOW: 5000

 5.Links Existence & Links Execution:
 -----------------------------------------
   Where exactly the links are placed----- Links existence
   Links are navigating to proper page or not ----Links execution.

  3 kinds of Links:
   1.Internal links: navigate to the same but different section.  
   2.External links:When i click on the link which will navigate to some other page. 
   3.Brokens links:Link will be there,but it doesn't have any action, when i click, which will not navigate anywhere.

 6.Cookies & Sessions:
    Cookies: These are temporary files created by browser while browsing the pages through internet.
    Cookies Testing: 
	->whether the browser is saving the cookies or not for that application called cookies testing.
	->especially we do this testing for web applications only.
        ->Cookies are related to the browser.It is created at the client side, wherever we are using the application.
    
   Sessions:
     ->Session will be created on the server side.
     ->Sessions are time slots created by the server. Session will be expired after some time(If you are idle for some time)



NON-FUNCTIONALITY TESTING:
--------------------------------------------------------------------------------------------------------------------------

->Once the functionality has done successfully.Then we go for non functionality testing.

   1)Performance Testing:
	 ->Load Testing
	 ->Stress Testing
	 ->Volume Testing
   2)Security Testing
   3)Recovery Testing
   4)Compatibility Testing
   5)Configuration Testing
   6)Installation Testing
   7)Sanitation/Garbage Testing


   Focus on customer expectation:
   1)Peformance----- speed of the application
	->Load
	->stress
	->volume
     Load: gradually Increasing the load on the application slowly then check the speed of the application.
     stress: Suddenly increase/decrease the load on the application and check the speed of the application.(checking stability)
     volume: checking How much data is able to handle by application is called volume testing.
  
  2)Security testing: How secure our application.
    
    Authentication:  Users are valid or not eg:login
    Authorization/Access control : verifying the permissions of the valid user.(what are the features can able to access)
